# Rivalt v0.4 テストケース

設計: [`design-v0.4.md`](./design-v0.4.md) · お知らせ: [`design-announcements.md`](./design-announcements.md)

## 前提

- v0.3 受け入れ済み
- `firestore.rules`（`seasons` / `config` / `announcements.category` / `announcementReads`）デプロイ済み
- テスト時 `VITE_LEAGUE_ID=dev`、本番確認時 `main`
- `leagues/{leagueId}/seasons/season1` と `config/league` が存在（または `/admin/seasons` で Season 1 を登録）

## SN. シーズン

### TC-SN1 既存試合の互換  〇

- 手順: `seasonId` なしの旧試合がある状態で Season 1 フィルタを表示
- 期待: 旧試合は Season 1 に含まれる。通算にも含まれる。

### TC-SN2 新規試合の紐づけ（期間優先）〇

- 前提: いまの日時が `season2` の `startsAt`〜`endsAt` 内。`config.activeSeasonId` は `season1` でも可。
- 手順: 管理者が試合追加
- 期待: `games` doc の `seasonId` は **期間内のシーズン**（例: `season2`）。config のみに依存しない。

### TC-SN3 期間外・未設定時の採番　〇

- 前提: どのシーズン期間にも現在日時が入らない（または期間未設定のみ）
- 手順: 試合追加
- 期待: `seasonId` は `config/league.activeSeasonId` と一致。

### TC-SN4 ランキング切替 〇

- 手順: `/ranking` で通算 ↔ 各シーズンを切替
- 期待: ポイント・試合数がフィルタに応じて変わる。`showInRanking: false` のシーズンは切替に出ない。

### TC-SN5 プレイヤー詳細 〇

- 手順: `/players/:id` でシーズン切替
- 期待: 各シーズンの pt・率・直近5戦が通算と独立。非表示シーズンは切替に出ない。

### TC-SN6 通算回帰 〇

- 手順: v0.3 時点の通算順位と比較（同一データ・同一メンバー）
- 期待: 通算モードで順位・pt が一致。

### TC-SN7 期間の重複拒否 〇

- 手順: `/admin/seasons` で既存シーズンと重なる開始〜終了を保存
- 期待: エラー表示。Firestore に重複期間は書き込まれない。

### TC-SN8 表示名 〇

- 手順: 表示名を変更して保存（24文字以内）
- 期待: ランキング・ホーム日程・管理画面に新ラベル。内部 ID（`season1` 等）は変わらない。

### TC-SN9 ランキング非表示 〇

- 手順: シーズンの「ランキング・個人成績のシーズン切替に表示」を OFF
- 期待: `/ranking` とプレイヤー詳細の切替から消える。試合採番・ホーム日程表示は従来どおり。

### TC-SN10 シーズン別ポイントルール 〇

- 手順: `/admin/seasons` でシーズン A のルールを変更（例: 1位 +10）→ そのシーズンに紐づく試合を追加
- 期待: 登録時の pt が新ルールどおり。既存試合の `results.point` は変わらない。
- 手順: `/ranking` でシーズン A を選択
- 期待: 下部のポイントルール表示がカスタム値。
- 手順: 「標準に戻す」で保存
- 期待: `pointRules` フィールド削除相当。以降は標準 (+7/+5/…) で計算。

## AN. お知らせ（種別・未読）

### TC-AN1 種別バッジ 〇

- 手順: 管理者が重要 / アップデート / 不具合修正 をそれぞれ投稿
- 期待: 一覧・詳細に種別ラベル（色分け）が表示される。

### TC-AN2 未読バッジ 〇

- 前提: ログイン済み
- 手順: 未読のお知らせがある状態でヘッダのメガホンを確認
- 期待: 未読件数バッジ。重要のみで赤アイコンにはしない（v0.4）。
- 手順: 1件の詳細を開く
- 期待: その件は既読。バッジ件数が減る。

### TC-AN3 テンプレート投稿 〇

- 手順: `/admin/announcements` で種別テンプレートを使って投稿
- 期待: 冒頭・末尾の定型文が本文に含まれる。

## HM. ホーム UI

### TC-HM1 お知らせボタン 〇

- 手順: ホームでヘッダ付近のお知らせ（メガホン）をタップ
- 期待: 一覧モーダル。ホーム本文に長いお知らせカードはない。

### TC-HM2 お知らせ詳細 〇

- 手順: 一覧の1件をタップ
- 期待: 詳細モーダルで全文。閉じると一覧に戻れる。
 
### TC-HM3 アクティビティ 〇

- 期待: ヘッダーに 🕐 アイコン（新着1時間以内は件数バッジ）。タップでモーダル一覧（最大15件・NEW・日時1行）。
- 期待: 新着があるときだけホームに「新しい動きがあります」バナー（最新1件の概要・タップで同モーダル）。新着なし時はホームにアクティビティ欄なし。

## AD. 管理者

### TC-AD1 シーズン管理（期間・表示名） 〇

- 手順: `/admin/seasons` で新シーズン追加（表示名・期間任意）
- 期待: 一覧に追加。期間内なら試合採番がそのシーズンに付く。**「有効化」ボタンはない**（v0.3 設計の active 切替は廃止）。

### TC-AD2 Season 1 初回登録 〇

- 前提: Firestore に seasons が無い
- 手順: 「Season 1 を登録する」
- 期待: `season1` と `config.activeSeasonId` が作成される。

### TC-AD3 お知らせ CRUD 〇

- 手順: `/admin/announcements` で作成・編集・削除
- 期待: ホームのお知らせモーダルに反映。
